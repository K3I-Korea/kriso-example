# 00. 무엇을 만드는가, 그리고 바로 돌려 보기

이 교재는 OpenBridge 위에 K3I 디자인 시스템을 얹어 자율운항선박 대시보드를 만들고, **자연어 요청만으로 그 디자인을 바꾸는** 방법을 따라 하도록 적었다. 이 장을 끝내면 대시보드가 손에서 돌아간다.

## 0-1. 전체 그림

목표는 이것이다. "야간 경보색을 더 어둡게", "배기온도 경보를 440도로", "개요 화면 오른쪽에 칸 하나 더" 같은 **말로 된 요청**을, 코드를 거의 건드리지 않고 **선언 파일(JSON) 수정**으로 끝내고, 그 변경이 화면과 Figma 에 함께 반영되게 하는 것이다.

그러려면 바뀔 수 있는 것을 전부 `design/` 폴더의 JSON 으로 빼 두어야 한다.

```
design/ (선언 — 자연어 변경의 대상)
   │  tokens.json · states.json · panels.json · layouts.json · views/*.json · signals.json
   ▼
scripts/validate.mjs (npm run check) — 잘못된 선언을 막는다
   ▼
src/ (코드) : domain(상태 결정) · ds(패널) · view(JSON→화면) · app(앱 골격)
   ▼
화면(React 대시보드)  +  Figma (같은 이름 규칙으로 반영)
```

### 먼저 알아 둘 말

- **OpenBridge**: 해양·선박 조타실(bridge)용으로 공개된 HMI(사람-기계 화면) 디자인 시스템. 이 프로젝트는 그 웹 컴포넌트 묶음 `@oicl/openbridge-webcomponents`(Lit 기반)를 가져다 쓴다.
- **HMI (Human-Machine Interface)**: 사람이 기계를 보고 조작하는 화면.
- **계기(Instrument)**: 나침반·타각계·수치 표시처럼 값을 보여 주는 OpenBridge 부품. 이 프로젝트에서 **고치지 않고 조합만** 한다.
- **프리미티브(Primitive)**: 버튼·토글·배지 같은 가장 작은 OpenBridge 부품. 역시 고치지 않는다.
- **토큰(Token)**: 색·간격·글꼴 같은 디자인 값의 이름. 여기서는 OpenBridge 변수를 가리킨다(02장).
- **블록(Block)**: 패널 한 종류(예: 타각 패널)와 그 상태 표현 규칙.
- **레이아웃(Layout)·뷰(View)**: 슬롯 배치와 화면 구성.
- **신호(Signal)**: 선박에서 올라오는 값 하나(예: 선수방위 HDG, 배기온도). 토픽·임계값·수명(ttl)을 가진다.

## 0-3. 설치하고 실행하기

압축을 풀고 `k3i-openbridge-lab` 폴더로 들어간다. 앞으로 모든 명령은 이 폴더에서 실행한다.

```bash
cd k3i-openbridge-lab
npm install
npm run dev
```

브라우저에서 **http://localhost:5173** 을 연다. 선박 대시보드가 나오면 성공이다. (멈출 때는 터미널에서 `Ctrl + C`.)

### `npm run dev` 가 바로 화면만 띄우지 않는 까닭

`package.json` 을 보면 `"dev": "vite"` 앞에 `"predev": "npm run setup:font && npm run check && npm run tokens"` 가 있다. npm 은 `dev` 를 실행하기 **전에 `predev` 를 자동으로** 돌린다. 그래서 `npm run dev` 한 번이 차례로 이렇게 한다.

1. `setup:font` — 글꼴을 준비한다(`scripts/copy-font.mjs`).
2. `check` — 선언(`design/*.json`)이 올바른지 검사한다(`scripts/validate.mjs`). 틀렸으면 여기서 멈춘다.
3. `tokens` — `design/tokens.json` 을 `src/styles/k3i-tokens.css` 로 빌드한다.
4. 그다음에야 Vite 개발 서버가 뜬다.

즉 **"검사 → 토큰 빌드 → 화면"** 순서가 한 명령에 들어 있다. 검사를 통과하지 못하면 화면이 아예 안 뜨므로, 잘못된 선언으로 작업을 끝내는 일을 막아 준다.

## 0-4. 화면에서 해 볼 것

1. **오른쪽 시나리오 토글**: 6가지 상태(정상·품질 저하·갱신 없음·신호 없음·경보·수동)를 하나씩 일으켜 본다. 값의 색·형태·문구가 상태에 따라 바뀐다.
2. **상태 검사 표**: 데이터 계층이 여러 상태 후보 중 **무엇을 왜 골랐는지**, 그것이 Figma 의 어느 variant 에 해당하는지 보여 준다(03장에서 원리를 다룬다).
3. **오른쪽 위 밝기 버튼**: 팔레트를 bright·day·dusk·night 로 바꾼다. OpenBridge 색이 바뀌고, K3I 패널도 자동으로 따라간다(02장).

## 0-5. 6계층 한눈에 보기

이 프로젝트의 디자인은 여섯 층으로 나뉜다. 자연어 요청이 들어오면 **어느 층을 바꾸는 일인지** 먼저 판단한다(상세는 01장).

| 층 | 무엇 | 바꾸는 곳 |
|---|---|---|
| View | 화면 = 레이아웃 + 패널 + 신호 연결 | `design/views/*.json` |
| Layout | 슬롯 배치(grid areas) | `design/layouts.json` |
| Block | 패널 종류·상태 표현 | `design/panels.json`, `design/states.json` |
| Instrument | 계기(나침반·타각계·수치) | OpenBridge 제공 — 조합만 |
| Primitive | 버튼·토글·배지 | OpenBridge 제공 |
| Token | 색·간격·글꼴 | `design/tokens.json` |
| (데이터) | 신호 카탈로그·임계값·ttl | `design/signals.json` |

> **📦 왜 코드가 아니라 선언(JSON)으로 빼 두나?**
>
> 색·임계값·화면 구성을 코드 여기저기에 적어 두면, 바꿀 때마다 그 코드를 찾아 고치고 다시 빌드해야 한다. 사람이 손대다 틀리기 쉽다. 이 프로젝트는 바뀔 수 있는 것을 `design/*.json` **선언**으로 모아, 자연어 요청 대부분을 **JSON 한두 곳 수정**으로 끝내게 했다. 코드는 "그 선언을 읽어 화면을 그리는" 일만 한다. 그래서 디자이너·기획자가 코드를 몰라도 무엇을 바꿀지 말할 수 있고, `npm run check` 가 틀린 선언을 막는다.

> **📦 OpenBridge 를 안 쓰고 계기를 직접 만들면?**
>
> 나침반·타각계 같은 계기를 손수 만들 수도 있지만, 해양 HMI 에는 야간 시인성·색 규칙·안전 표기 같은 까다로운 표준이 있다. OpenBridge 는 그 표준을 지킨 계기·색 팔레트를 이미 담고 있어, 가져다 조합하면 표준을 공짜로 얻는다. 그래서 이 프로젝트는 계기·프리미티브를 **고치지 않고 조합만** 한다. 대신 그 위에 K3I 만의 패널·레이아웃(Block·Layout·View)을 얹는다.

> **📦 `npm run dev` 가 느리게 느껴지면? (predev 때문이다)**
>
> 화면이 뜨기 전에 글꼴 준비·검사·토큰 빌드가 먼저 돈다(0-3). 코드를 안 바꾸고 화면만 다시 보고 싶으면, 서버를 켠 채 두고 브라우저만 새로 고치면 된다. 선언이나 토큰만 바꿨을 때는 `npm run check`·`npm run tokens` 를 따로 돌려 확인할 수도 있다.

## 이 장에서 한 것

- 프로젝트를 설치하고 `npm run dev` 로 대시보드를 띄웠다.
- `npm run dev` 가 "검사 → 토큰 빌드 → 화면" 순서로 도는 것을 봤다.
- 시나리오 토글·상태 검사 표·밝기 팔레트를 눈으로 봤다.
- 6계층과 "선언으로 빼 둔다" 는 생각을 봤다.

다음 **01장**에서는 6계층을 하나씩 보고, 자연어 요청이 어느 층을 바꾸는 일인지 판단하는 법을 익힌다.
