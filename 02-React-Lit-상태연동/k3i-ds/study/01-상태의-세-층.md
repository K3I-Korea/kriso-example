# 01. 상태의 세 층 — 같은 상태, 세 이름

2강 전체를 꿰는 그림이 하나 있다. 같은 "상태" 가 **세 곳에서 다른 이름으로** 나타나고, 그 셋을 1:1로 맞추는 것이 상태 연동의 핵심이다.

## 1-1. 세 층

자율운항 스위치가 "켜짐" 이라는 상태를 예로 든다.

| 층 | 상태를 부르는 이름 | 예 (자율운항 스위치) |
|---|---|---|
| **Figma** | Component Set 의 **variant** | `checked = true` |
| **Lit**(웹 컴포넌트) | `@property({ reflect: true })` → **HTML 속성** | `<ds-switch checked>` |
| **React**(앱) | **state** → props 로 전달 | `const [autopilot, setAutopilot] = useState(false)` |

세 이름이 가리키는 것은 같은 "켜짐" 이다. 디자이너는 Figma variant 로 그리고, 컴포넌트는 HTML 속성으로 들고, 앱은 state 로 쥔다.

## 1-2. 상태는 어느 방향으로 흐르나

이 실습에서 상태의 **소유자는 React** 다. 흐름은 이렇다.

```
React state ──props──▶ Lit @property ──reflect──▶ HTML 속성 ──(규칙)──▶ Figma variant
     ▲                      │
     └──── ds-change 이벤트 ◀┘   (React 가 preventDefault 하면 Lit 이 되돌림)
```

- **내려가는 방향**(React → Figma): React 가 `checked={autopilot}` 로 값을 내려보내면, Lit 이 `reflect` 로 HTML 속성 `checked` 를 붙이고, 그 속성이 Figma variant `checked=true` 와 짝을 이룬다.
- **올라오는 방향**(Lit → React): 사용자가 스위치를 누르면 Lit 이 `ds-change` 이벤트로 "눌렸다" 를 알리고, React 가 받아서 state 를 바꿀지 말지 정한다.

## 1-3. 소유자는 하나여야 한다

같은 값을 React 와 Lit 이 **각자** 쥐면, 둘이 달라졌을 때 어느 쪽이 맞는지 알 수 없다. 그래서 소유자를 하나로 정한다. 이 실습은 **React 가 소유**하고, Lit 은 두 가지만 한다.

1. React 가 내려 준 값대로 **그린다**.
2. 사용자 입력을 이벤트로 **알린다**(스스로 상태를 확정하지 않는다).

켤지 말지의 최종 결정은 React 가 내린다. 그래서 "잠금 중이면 거부" 같은 규칙을 한 곳(React)에서 넣을 수 있다.

> **📦 Lit 이 상태를 소유하면? — 거부·동기화가 어긋난다**
>
> 스위치가 눌릴 때 **스스로** 켜지고 끝낸다면, React 는 그 사실을 나중에야 알게 된다. "원격 잠금 중이면 켜지 못하게" 를 넣으려면, 스위치가 잠금 값까지 알아야 하는데 그것은 앱의 사정이라 스위치가 알 수 없다. 두 쪽이 상태를 나눠 쥐면 값이 틀어지고 거부 처리가 꼬인다. 그래서 **소유는 한 곳(React), 통지는 이벤트** 로 가른다.

> **📦 reflect 가 없으면? — Figma variant·CSS 가 상태를 못 본다**
>
> `@property` 에 `reflect: true` 가 없으면, 값은 컴포넌트 안에만 있고 HTML 속성으로 나오지 않는다. 그러면 `<ds-switch>` 를 겉에서 봐도 켜졌는지 알 수 없고, `:host([checked])` 같은 CSS 선택자도 안 맞으며, 02강의 관찰 표(DOM 속성)와 Figma variant 매핑도 못 한다. reflect 가 **상태를 바깥(HTML·CSS·Figma)으로 잇는 다리**다. 자세한 것은 02장에서 본다.

## 이 장에서 한 것

- 같은 상태가 Figma variant · Lit 속성 · React state 세 이름으로 나타남을 봤다.
- 상태가 React(소유) → Lit → HTML → Figma 로 내려가고, 이벤트로 올라옴을 봤다.
- 소유자를 하나로 두는 까닭을 봤다.
