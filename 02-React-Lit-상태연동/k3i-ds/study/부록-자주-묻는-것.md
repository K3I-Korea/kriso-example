# 부록 — 자주 묻는 것

2강(상태 연동)을 따라 하다 자주 나오는 물음을 모았다.

## 취소 가능한 이벤트(cancelable / `preventDefault`)란

`ds-switch` 의 `ds-change` 는 **취소 가능한 이벤트**다. 부모(React)가 `preventDefault()` 를 부르면, 스위치가 바뀌려던 것을 **되돌린다.** `ds-switch.ts` 의 `toggle()` 이 그 구조다.

```ts
const previous = this.checked;
this.checked = !previous;                 // ① 먼저 낙관적으로 바꾼다
const ev = new CustomEvent("ds-change", { ..., cancelable: true });
if (!this.dispatchEvent(ev)) this.checked = previous;   // ③ 부모가 거부하면 되돌린다
```

- `cancelable: true` 로 이벤트를 만들면, 부모가 그 이벤트에 `preventDefault()` 를 부를 수 있다.
- `dispatchEvent()` 는 **거부당했으면 `false` 를 돌려준다.** 그래서 `if (!this.dispatchEvent(ev))` 가 "거부되었나" 를 묻는 것이고, 그러면 `previous` 로 되돌린다.
- 03장의 "원격 잠금" 이 이 구조를 쓴다. 잠금이 켜져 있으면 React 의 `onAutopilotChange` 가 `e.preventDefault()` 를 불러 토글을 거부한다.

**왜 먼저 바꾸고 되돌리나(낙관적 갱신)**: 대부분의 경우는 거부되지 않으므로, 먼저 바꿔 두면 화면이 즉시 반응한다. 드물게 거부될 때만 되돌린다.

## `reflect: true` 는 무엇을 하나

`@property({ reflect: true })` 는 **속성 값을 HTML 속성으로 내보낸다.** 예를 들어 `checked = true` 가 되면 요소에 `checked` 라는 HTML 속성이 붙는다. 이것이 중요한 까닭은 셋이다.

1. CSS 가 `:host([checked])` 로 그 값을 보고 모양을 고를 수 있다.
2. `MutationObserver`(04장의 관찰 표)가 그 속성을 읽을 수 있다.
3. 그 HTML 속성이 곧 Figma variant 와 1:1로 맞는다.

`reflect` 가 없으면 값은 바뀌어도 HTML 속성으로 나가지 않아, 위 셋이 모두 동작하지 않는다. 그래서 바깥·화면·Figma 가 알아야 하는 공개 상태(`checked`·`disabled`)에는 `reflect: true` 를 둔다.

## `@property` 와 `@state` 는 뭐가 다른가

| | `@property` | `@state` |
|---|---|---|
| 누가 쓰나 | 바깥(React 등)이 제어 | 컴포넌트 내부 전용 |
| HTML 속성으로 노출 | `reflect: true` 면 노출 | 노출 안 함 |
| 예(`ds-switch`) | `checked`·`disabled` | `pressed` |

바깥이 알아야 하는 공개 상태는 `@property`, "지금 누르고 있다" 같은 내부 사정은 `@state` 로 둔다. 더 자세한 구분은 1강 03장(Lit 컴포넌트 뜯어보기)과 이 교재 02장에 있다.
