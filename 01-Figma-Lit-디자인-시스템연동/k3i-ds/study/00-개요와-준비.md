# 00. 무엇을 만드는가, 그리고 바로 돌려 보기

이 교재는 Figma 디자인을 한 번만 구현해서 React·Vue·순수 HTML 어디서나 똑같이 쓰는 방법을, Figma 연결부터 차근차근 따라 하도록 적었다. 이 장을 끝내면 프로젝트가 손에서 돌아가고, 다음 장부터 Figma와 잇는다.

따라만 하면 되도록 모든 명령과 눌러야 할 것을 그대로 적었다. 먼저 전체 그림을 한 번 보고, 바로 실행으로 들어간다.

## 0-1. 전체 그림

디자인 값 하나(예: 브랜드 색)를 바꾸면, 그 값을 쓰는 버튼·입력칸·카드가 React에서도 HTML에서도 한꺼번에 바뀌게 만드는 것이 목표다. 그러려면 값과 컴포넌트를 한 곳에서만 정하고 나머지는 그걸 따라오게 해야 한다.

```
Figma (디자인)
   │  토큰을 내보냄 → tokens/tokens.json
   ▼
Style Dictionary (scripts/build-tokens.mjs)
   │  → src/styles/tokens.css  (--ds-* CSS 변수, 라이트/다크)
   ▼
Lit 컴포넌트 (src/components/*.ts)   ← 디자인을 코드로 옮긴 단일 공급원
   │  Shadow DOM 으로 스타일을 격리하고, 토큰만 CSS 변수로 통과시킴
   ▼
├─ 순수 HTML / 서버 템플릿 : <ds-button>
├─ Vue / Angular / Svelte  : <ds-button> 그대로
└─ React                   : @k3i/ds/react (자동 생성 래퍼)
```

### 먼저 알아 둘 말

이 프로젝트 안에서 특정한 뜻으로 쓰는 말만 한 줄씩 풀어 둔다. 나올 때마다 다시 설명하지 않는다.

- **디자인 토큰(design token)**: 색·간격·반경·글꼴 같은 디자인 값을 이름으로 정해 둔 것. 예를 들어 `#3b5bdb` 라는 색을 `semantic.primary` 라는 이름으로 부른다.
- **웹 컴포넌트(web component)**: 브라우저가 기본으로 지원하는 재사용 UI 요소. `<ds-button>` 처럼 직접 만든 태그로 쓴다. 특정 프론트앤드 프레임워크에 묶이지 않는다.
- **Lit**: 웹 컴포넌트를 특정 프론트앤드 프레임워크에 종속되지 않는 독립적인 UI 디자인+코드 덩어리로 만들어주는 경량 라이브러리로서 순수 JS로만 구현함.
- **Shadow DOM**: 컴포넌트 안쪽의 구조와 스타일을 바깥과 격리하는 브라우저 기능. 바깥 CSS가 컴포넌트 속으로 들어오지 못한다.
- **Figma MCP (Model Context Protocol)**: Claude Code가 Figma 파일을 읽고 쓰도록 잇는 연결. 01장에서 붙인다.
- **Style Dictionary**: 토큰 JSON을 CSS 변수 같은 실제 코드로 바꿔 주는 도구.

## 0-3. 프로젝트 열고 설치하기

압축을 받았다면 풀고, 그 안의 `k3i-ds` 폴더로 들어간다. 앞으로 모든 명령은 이 `k3i-ds` 폴더에서 실행한다.

```bash
cd k3i-ds
npm install
```

`npm install` 은 `package.json` 에 적힌 라이브러리(Lit, Style Dictionary, Vite 등)를 `node_modules` 폴더에 내려받는다. 처음 한 번만 하면 된다. 끝나면 폴더에 `node_modules` 가 생긴다.

## 0-4. 데모 실행하기 — 실습 1

```bash
npm run dev
```

이 한 줄이 두 가지를 한다.

1. **토큰 빌드**: `tokens/tokens.json` 을 읽어 `src/styles/tokens.css` 를 다시 만든다. (`package.json` 의 `"dev": "npm run tokens && vite"` 에서 `npm run tokens` 가 먼저 돈다.)
2. **개발 서버 실행**: Vite 가 `http://localhost:5173` 에서 데모를 띄운다.

브라우저에서 **http://localhost:5173** 을 연다. `@k3i/ds — Lit 디자인 시스템` 화면이 나오면 성공이다. (이 화면은 프로젝트 맨 위의 `index.html` 이다.)

> 서버를 멈출 때는 터미널에서 `Ctrl + C` 를 누른다.

## 0-5. 화면에서 다섯 가지를 확인한다

실행된 화면에서 아래를 차례로 해 본다. 각 항목은 디자인 시스템이 어떻게 동작하는지를 눈으로 보여 준다.

### ① 버튼 종류와 크기

첫 카드 `Button variants / sizes` 에 버튼이 줄지어 있다. Primary·Secondary·Ghost·Danger 는 색이 다른 종류(variant)이고, Small·Medium·Large 는 크기(size)다. `Disabled` 는 흐리게, `저장 중` 은 도는 표시가 붙는다. 전부 같은 `<ds-button>` 하나에 속성만 달리 준 것이다.

### ② 다크 테마 전환 — 코드를 안 고쳤는데 색이 바뀐다

오른쪽 위 **`다크 테마 전환`** 버튼을 누른다. 화면 전체가 어두운 색으로 바뀐다.

- 바뀐 것은 **컴포넌트 코드가 아니다.** 버튼을 누르면 문서의 `data-theme` 가 `dark` 로 바뀌고(`index.html` 아래쪽 script), 그러면 `tokens.css` 안의 `:root[data-theme="dark"] { ... }` 묶음이 켜지면서 색 토큰만 다른 값으로 교체된다.
- 확인: 편집기로 `src/styles/tokens.css` 를 열어 `data-theme="dark"` 를 찾는다. 거기 적힌 `--ds-semantic-*` 값이 밝은 테마와 어떻게 다른지 본다. 색을 바꾸는 데 컴포넌트는 손대지 않았다는 것이 핵심이다.

### ③ 전역 CSS 공격 실험 — Shadow DOM 이 지켜 준다

`전역 CSS 공격 실험` 카드에는 일부러 공격적인 전역 CSS 가 걸려 있다(노란 배경, 빨간 글자, 패딩 제거 등). 같은 카드 안에 일반 `<button>`·`<input>` 과 `<ds-button>`·`<ds-input>` 이 나란히 있다.

- 일반 `<button>`·`<input>` 은 그 CSS 를 맞고 모양이 망가진다.
- `<ds-button>`·`<ds-input>` 은 그대로다. Shadow DOM 이 바깥 스타일을 막기 때문이다.
- 확인: `<ds-button>` 위에서 마우스 오른쪽 → **검사(Inspect)** 를 눌러 개발자 도구를 연다. 요소 트리에서 `ds-button` 을 펼치면 `#shadow-root (open)` 이 보인다. 컴포넌트의 진짜 내용이 그 안에 따로 들어 있어서 바깥 CSS 가 닿지 못한다.

### ④ 폼 검증과 제출

`폼 연동 (ElementInternals)` 카드에서:

1. 아무것도 입력하지 않고 **`가입`** 을 누른다. → 두 입력칸이 빨갛게 되고 오류 글이 뜬다. 아래 회색 칸에 `검증 실패 — 빨간 필드를 확인하세요` 가 나온다.
2. 이름과 올바른 이메일을 넣고 다시 **`가입`** 을 누른다. → 아래 칸에 입력한 값이 `FormData` 로 정리돼 나온다.
3. **`초기화`** 를 누르면 입력칸이 비워진다.

`<ds-input>` 은 브라우저 기본 입력칸처럼 폼에 연결돼 있어서, 검증과 제출이 일반 폼과 똑같이 동작한다.

### ⑤ 확인 질문 — 토큰 하나를 바꿔 본다

디자인 값을 한 곳에서 바꾸면 전부 따라오는지 직접 해 본다.

1. 편집기로 `tokens/tokens.json` 을 연다.
2. `color` → `brand` → `600` 의 값을 다른 색으로 바꾼다. 예를 들어 `"#3b5bdb"` 를 보라색 `"#7048e8"` 로 바꾼다.
3. 저장하고 터미널에서 다시 빌드한다. `npm run dev` 가 아직 돌고 있다면 한 번 멈췄다가(`Ctrl + C`) 다시 실행하거나, 토큰만 다시 만들려면 다음을 실행한다.

```bash
npm run tokens
```

4. 브라우저를 새로 고친다. **Primary 버튼과 가입 버튼 색이 바뀐다.**

왜 바뀌는가. `tokens.json` 에서 `semantic.primary` 는 `{color.brand.600}` 을 가리키고(별칭), Primary 버튼은 `var(--ds-semantic-primary)` 를 쓴다. 그래서 `brand.600` 하나만 바꿔도 그 색을 쓰는 곳이 모두 따라온다. 바꾼 값은 원래대로 되돌려 두고 다음 장으로 간다.

## 0-7. 빌드 스크립트와 설정 파일 한 줄씩 읽기 (심화)

아래는 프로젝트를 돌리는 데 꼭 읽지 않아도 된다. 처음에는 건너뛰고, 02·06장을 본 뒤 "이 설정이 왜 이렇게 생겼나"가 궁금할 때 돌아와도 된다. 실제 파일을 그대로 인용해 한 줄씩 푼다.

### 먼저 알아 둘 말

- **번들러(bundler)**: 여러 소스 파일과 라이브러리를 묶어 브라우저가 바로 쓸 파일로 만드는 도구. 이 프로젝트의 번들러는 Vite 다.
- **ES 모듈(ES Module)**: `import`/`export` 문법을 쓰는 요즘 자바스크립트 모듈 방식.
- **타입 선언 파일(`.d.ts`)**: 값은 없고 타입 정보만 담은 파일. 이 라이브러리를 쓰는 앱이 자동 완성과 타입 검사를 받게 해 준다.

### (1) `scripts/build-tokens.mjs` — 토큰 JSON 을 CSS 로

`npm run tokens` 가 실행하는 파일이다. Style Dictionary 로 `tokens.json` 을 CSS 변수로 바꾼다.

```js
import StyleDictionary from "style-dictionary";
import { mkdirSync, readFileSync, writeFileSync } from "node:fs";

const PREFIX = "ds";
const OUT = "src/styles/";
```

- 1행: 변환 도구 Style Dictionary 를 불러온다.
- 2행: 파일을 만들고 읽고 쓰는 Node 기본 기능을 불러온다(마지막에 두 CSS 를 합칠 때 쓴다).
- 4행: 모든 CSS 변수 앞에 붙일 말 `ds`. → `--ds-...` 가 여기서 나온다.
- 5행: 출력 폴더 `src/styles/`.

```js
const light = new StyleDictionary({
  source: ["tokens/tokens.json"],
  platforms: {
    css: {
      transformGroup: "css",
      prefix: PREFIX,
      buildPath: OUT,
      files: [
        { destination: "tokens.light.css", format: "css/variables",
          options: { selector: ":root", outputReferences: true } },
      ],
    },
    js: {
      transformGroup: "js",
      buildPath: OUT,
      files: [{ destination: "tokens.js", format: "javascript/es6" }],
    },
  },
});
```

라이트(기본) 테마 설정이다.

- `source`: 읽을 토큰 파일. 여기 있는 토큰이 모두 출력 대상이 된다.
- `transformGroup: "css"`: 토큰 이름을 `--ds-semantic-primary` 처럼 바꾸고, 값을 CSS 에 맞게 바꾸는 변환 묶음.
- `prefix`: 위의 `ds`.
- `buildPath`: 출력 폴더.
- `files` 의 css: `tokens.light.css` 로, 형식은 `css/variables`, 선택자는 `:root`(문서 전체), `outputReferences: true` 는 별칭을 풀어 쓰지 않고 `var(--ds-...)` 참조를 그대로 살려 둔다는 뜻이다. 그래서 `semantic.primary` 는 숫자 색이 아니라 `var(--ds-color-brand-600)` 로 나온다.
- `js` 묶음: 같은 토큰을 `tokens.js`(자바스크립트 상수)로도 낸다.

```js
const dark = new StyleDictionary({
  include: ["tokens/tokens.json"],
  source: ["tokens/themes/dark.json"],
  platforms: {
    css: {
      transformGroup: "css",
      prefix: PREFIX,
      buildPath: OUT,
      files: [
        { destination: "tokens.dark.css", format: "css/variables",
          filter: (token) => token.filePath.includes("themes/dark"),
          options: { selector: ':root[data-theme="dark"], .ds-theme-dark',
                     outputReferences: true } },
      ],
    },
  },
});
```

다크 테마 설정이다. 라이트와 두 곳이 다르다.

- `include` 와 `source` 를 나눠 쓴다. `include`(`tokens.json`)는 **참조를 풀기 위해서만** 넣고 출력하지 않는다. `source`(`dark.json`)만 출력 대상이다. 다크가 `{color.brand.300}` 같은 원시 색을 가리키려면 원시 색 정의가 있어야 하므로 `include` 로 넣어 둔다.
- `filter`: 파일 경로에 `themes/dark` 가 들어간 토큰만 출력한다. 즉 다크에서 실제로 덮어쓴 색만 나온다.
- `selector`: `:root[data-theme="dark"], .ds-theme-dark`. 00장에서 "다크 테마 전환" 버튼이 켠 것이 바로 이 선택자다.

```js
await light.buildAllPlatforms();
await dark.buildAllPlatforms();

mkdirSync("dist", { recursive: true });
const merged =
  readFileSync(OUT + "tokens.light.css", "utf8") + "\n" +
  readFileSync(OUT + "tokens.dark.css", "utf8");
writeFileSync(OUT + "tokens.css", merged);
writeFileSync("dist/tokens.css", merged);
console.log("✔ tokens.css 생성 완료");
```

- 앞 두 줄: 라이트·다크 설정을 각각 실행해 `tokens.light.css` 와 `tokens.dark.css` 를 만든다.
- `mkdirSync("dist", ...)`: 없으면 `dist` 폴더를 만든다.
- `merged`: 두 CSS 를 한 글자로 이어 붙인다(라이트 다음에 다크). 앱은 이렇게 합친 파일 하나만 불러 쓰면 라이트·다크가 모두 들어온다.
- 마지막 두 줄: 합친 내용을 `src/styles/tokens.css`(데모용)와 `dist/tokens.css`(배포용) 두 곳에 쓴다.

> 왜 Style Dictionary 인스턴스를 둘로 나눴나: 라이트는 모든 토큰을 `:root` 에 내고, 다크는 덮어쓴 색만 다른 선택자에 내야 하기 때문이다. 한 번에 내는 다른 방법도 있지만, 이 프로젝트는 둘로 나눠 합치는 쪽을 골랐다.

### (2) `package.json` — 프로젝트 정보·명령·의존성

이 파일이 프로젝트의 이름, 실행할 명령, 필요한 라이브러리를 정한다.

```json
{
  "name": "@k3i/ds",
  "version": "0.1.0",
  "description": "Figma 디자인 시스템 → 토큰(CSS 변수) → Lit 웹 컴포넌트 → React 래퍼",
  "type": "module",
  "main": "./dist/index.js",
  "module": "./dist/index.js",
  "types": "./dist/types/index.d.ts",
  "exports": {
    ".":            { "types": "./dist/types/index.d.ts",       "import": "./dist/index.js" },
    "./react":      { "types": "./dist/types/react/index.d.ts", "import": "./dist/react.js" },
    "./tokens.css": "./dist/tokens.css"
  },
  "files": ["dist"],
  "sideEffects": ["./dist/index.js", "./dist/tokens.css"],
  "scripts": { ... },
  "dependencies":     { "lit": "^3.2.0" },
  "peerDependencies": { "@lit/react": "^1.0.0", "react": ">=17" },
  "peerDependenciesMeta": {
    "react":      { "optional": true },
    "@lit/react": { "optional": true }
  },
  "devDependencies": { "@types/react": "...", "react": "...", "style-dictionary": "...", "typescript": "...", "vite": "..." }
}
```

- `name`: 패키지 이름. 앱에서 `import "@k3i/ds"` 로 부르는 그 이름이다.
- `version`: 패키지 버전.
- `description`: 한 줄 설명.
- `type: "module"`: 이 패키지의 `.js` 를 ES 모듈로 다룬다(위 `.mjs` 와 같은 이야기).
- `main` / `module`: 도구나 번들러가 `@k3i/ds` 를 불렀을 때 열 기본 파일(`dist/index.js`).
- `types`: 그 패키지의 타입 선언 진입 파일. (3)·(4)의 `tsconfig.build.json` 이 만든 `dist/types/index.d.ts` 를 가리킨다.
- `exports`: **이름마다 어떤 파일을 쓸지 정한 대응표.** `.` 는 기본(컴포넌트 전부), `./react` 는 React 래퍼, `./tokens.css` 는 CSS 다. 06장에서 `@k3i/ds`·`@k3i/ds/react`·`@k3i/ds/tokens.css` 로 불렀던 이름이 여기서 정해진다. 각 항목의 `types` 는 타입, `import` 는 실제 코드다.
- `files`: npm 에 올릴 때 넣을 폴더. 소스는 빼고 빌드 결과 `dist` 만 올린다.
- `sideEffects`: 번들러가 안 쓰는 코드를 지울 때(트리 셰이킹, tree-shaking, 안 쓰는 코드 덜어내기), 이 두 파일은 **불러오는 것만으로 효과가 있으니**(커스텀 엘리먼트 등록, CSS 적용) 지우지 말라고 알린다.
- `scripts`: 자주 쓰는 명령 목록. 자세한 설명은 부록 「자주 묻는 것」의 `scripts` 절에 있다.
- `dependencies`: 서비스가 돌 때도 꼭 필요한 라이브러리. 여기서는 `lit` 하나.
- `peerDependencies`: 이 패키지를 쓰는 **앱이 자기 쪽에 설치해야 하는** 라이브러리. React 래퍼가 쓰는 `react`·`@lit/react` 다. 이렇게 두면 앱의 React 와 다른 React 가 또 들어가는 것을 막는다.
- `peerDependenciesMeta` 의 `optional: true`: React 를 안 쓰는 앱(순수 HTML·Vue)은 `react`·`@lit/react` 를 설치하지 않아도 된다는 표시.
- `devDependencies`: 개발·빌드 때만 필요한 것들(타입 정의, `vite`, `style-dictionary`, `typescript`, 데모용 `react` 등). 앱에는 딸려 가지 않는다.

### (3) `tsconfig.json` — 타입 검사 설정

TypeScript 가 코드를 어떻게 이해하고 검사할지 정한다.

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "strict": true,
    "experimentalDecorators": true,
    "useDefineForClassFields": false,
    "skipLibCheck": true,
    "allowJs": true,
    "jsx": "react-jsx",
    "noEmit": true
  },
  "include": ["src", "demo"]
}
```

- `target`: 출력 기준 자바스크립트 버전(ES2022).
- `module` / `moduleResolution`: 모듈을 ES 모듈로 다루고, 경로를 번들러 방식으로 찾는다(Vite 가 번들러라서).
- `lib`: 쓸 수 있는 내장 타입. 최신 문법(ES2022)과 브라우저 DOM 타입을 켠다.
- `strict`: 엄격한 타입 검사를 켠다.
- `experimentalDecorators`: `@customElement`·`@property` 같은 데코레이터를 허용한다. Lit 이 이 문법을 쓴다.
- `useDefineForClassFields: false`: 클래스 필드를 옛 방식으로 처리한다. Lit 데코레이터가 `@property` 를 제대로 잡으려면 이 값이어야 한다.
- `skipLibCheck`: 외부 라이브러리의 타입 파일까지 다시 검사하지 않는다(검사 속도를 올린다).
- `allowJs`: `.js` 파일도 포함한다(생성된 `tokens.js` 등).
- `jsx: "react-jsx"`: `demo` 의 `.tsx` 를 React 방식으로 해석한다.
- `noEmit: true`: **타입 검사만 하고 파일은 내지 않는다.** 실제 빌드는 Vite 가 하기 때문이다.
- `include`: 검사할 폴더는 `src` 와 `demo`.

### (4) `tsconfig.build.json` — 타입 선언만 내는 설정

`npm run build` 의 마지막 단계 `tsc -p tsconfig.build.json` 이 쓰는 설정이다. 앱에 줄 `.d.ts` 를 만든다.

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "noEmit": false,
    "declaration": true,
    "emitDeclarationOnly": true,
    "declarationDir": "dist/types"
  },
  "include": ["src"],
  "exclude": ["src/styles/tokens.js"]
}
```

- `extends`: 위 `tsconfig.json` 을 상속하고, 아래 몇 가지만 덮어쓴다.
- `noEmit: false`: 이번에는 파일을 낸다(상속한 `true` 를 뒤집는다).
- `declaration: true` + `emitDeclarationOnly: true`: **자바스크립트는 내지 않고 타입 선언 파일(`.d.ts`)만 낸다.** 자바스크립트는 Vite 가 이미 내기 때문이다.
- `declarationDir`: 그 `.d.ts` 를 `dist/types` 에 둔다. `package.json` 의 `"types"` 가 이 폴더를 가리킨다.
- `include`: `src` 만(데모는 뺀다).
- `exclude`: 생성된 `src/styles/tokens.js` 는 선언을 만들 대상에서 뺀다.

### (5) `vite.config.ts` — 개발 서버와 라이브러리 빌드 설정

```ts
import { defineConfig } from "vite";
import { resolve } from "node:path";

export default defineConfig({
  root: ".",
  build: {
    outDir: "dist",
    emptyOutDir: false,
    lib: {
      entry: {
        index: resolve(__dirname, "src/index.ts"),
        react: resolve(__dirname, "src/react/index.ts"),
      },
      formats: ["es"],
    },
    rollupOptions: {
      external: [/^lit/, "react", "@lit/react"],
    },
  },
});
```

- `root: "."`: 개발 서버가 프로젝트 루트를 기준으로 연다. 그래서 `npm run dev` 에서 루트 `index.html` 은 `http://localhost:5173` 으로, `demo/react.html` 은 `http://localhost:5173/demo/react.html` 로 둘 다 열린다.
- `build.outDir`: 빌드 결과를 `dist` 에 둔다.
- `emptyOutDir: false`: **빌드 전에 `dist` 를 비우지 않는다.** `npm run build` 는 토큰 빌드를 먼저 해서 `dist/tokens.css` 를 만드는데, Vite 가 `dist` 를 비우면 그 파일이 사라지기 때문이다.
- `lib.entry`: 라이브러리 입구를 둘 둔다. `index`(컴포넌트 전부)와 `react`(React 래퍼). 각각 `dist/index.js`·`dist/react.js` 로 나온다.
- `formats: ["es"]`: ES 모듈 형식으로만 낸다.
- `rollupOptions.external`: `lit`·`react`·`@lit/react` 는 번들에 넣지 않는다. 이 라이브러리를 쓰는 앱이 그 라이브러리를 직접 설치해 쓰게 하려는 것이다. 같은 lit 이 두 벌 들어가는 것을 막는다.
