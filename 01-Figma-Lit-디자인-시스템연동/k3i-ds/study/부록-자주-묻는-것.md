# 부록 — 자주 묻는 것

실습을 따라 하다 자주 나오는 물음을 모았다.

## `.mjs` 는 무슨 확장자인가

`.mjs` 는 **JavaScript ES 모듈(ES Module) 파일** 확장자다. 앞의 `m` 이 module 을 뜻한다.

- 보통 `.js` 와 같은 자바스크립트지만, **Node.js 가 이 파일을 항상 ES 모듈로 다룬다.** 즉 `import ... from "..."` / `export` 문법을 쓸 수 있다(옛 방식인 `require(...)` 가 아니라).
- `.cjs` 는 반대로 항상 CommonJS(`require`)로 다뤄진다. `.js` 는 `package.json` 의 `"type"` 설정에 따라 둘 중 하나로 정해진다.
- 이 프로젝트의 `scripts/build-tokens.mjs`·`scripts/build-figma-plugin.mjs` 가 `.mjs` 인 까닭이 그것이다. 맨 윗줄이 `import StyleDictionary from "style-dictionary"` 처럼 ES 모듈 문법이라, 확장자를 `.mjs` 로 두면 설정과 무관하게 ES 모듈로 확실히 실행된다. (이 프로젝트는 `package.json` 에 `"type": "module"` 도 있어 `.js` 여도 ES 모듈이지만, `.mjs` 는 그것을 더 분명히 밝히는 것이다.)

실행은 `node scripts/build-tokens.mjs` 처럼 하면 된다. `npm run tokens` 도 안에서 이 파일을 실행하는 것이다.

## `package.json` 의 `scripts` 는 무엇을 하나

`scripts` 는 **자주 쓰는 명령에 짧은 이름을 붙여 두는 목록**이다. `npm run <이름>` 으로 그 이름에 적힌 명령을 실행한다. 긴 명령을 매번 외워 치지 않아도 되고, 팀이 같은 이름으로 같은 동작을 하게 맞춘다.

이 프로젝트(`k3i-ds`)의 `scripts`:

```json
"scripts": {
  "tokens":       "node scripts/build-tokens.mjs",
  "dev":          "npm run tokens && vite",
  "build":        "npm run tokens && vite build && tsc -p tsconfig.build.json",
  "preview":      "vite preview",
  "figma:plugin": "node scripts/build-figma-plugin.mjs",
  "figma:connect":"figma connect publish"
}
```

- `npm run tokens` → `node scripts/build-tokens.mjs` 를 실행한다. 이름은 왼쪽, 실제 실행되는 명령은 오른쪽이다.
- **`&&` 로 여러 명령을 이어 붙인다.** `dev` 는 `npm run tokens` 를 먼저 끝내고 그다음 `vite` 를 실행한다. 앞 명령이 실패하면 뒤는 돌지 않는다.
- **다른 script 를 불러 쓸 수 있다.** `dev`·`build` 가 안에서 `npm run tokens` 를 다시 부른다. 한 동작을 한 곳에만 적어 두고 여러 곳에서 재사용한다.

알아 두면 좋은 두 가지:

- **이름 몇 개는 `run` 을 생략한다.** `start`·`test` 는 `npm start`·`npm test` 로도 된다. 그 밖의 이름(예: `tokens`)은 반드시 `npm run tokens` 로 쓴다.
- **`pre`/`post` 접두 이름은 자동으로 붙어 돈다.** 3강 프로젝트(`k3i-openbridge-lab`)에는 `predev`·`prebuild` 가 있어서, `npm run dev` 를 하면 npm 이 먼저 `predev` 를 자동 실행한 뒤 `dev` 를 돈다(폰트 준비 → 검사 → 토큰 빌드). 이 프로젝트(`k3i-ds`)에는 `pre*` 가 없고, 대신 `dev` 안에서 `&&` 로 토큰 빌드를 먼저 한다.
