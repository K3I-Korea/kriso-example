# 07. 양방향 동기화 정리와 마무리

앞의 장을 하나로 꿰고, 새 컴포넌트를 추가할 때 지킬 것과 알아 둘 한계로 마무리한다.

## 7-1. 전체 흐름 다시 보기

```
 tokens.json ──(02)──▶ Figma Variables/Styles ──(04)──▶ Figma Components
      ▲                                                       │
      └──────(02 역방향)────── get_variable_defs ◀──────(05)───┘
                                                              │
                        Code Connect (05) ──▶ <ds-button> 코드 ──(06)──▶ React·Vue·HTML
```

- **값(토큰)**: 코드와 Figma 중 한쪽을 단일 공급원으로 정하고, 반대쪽은 받아만 간다(02장).
- **컴포넌트 모양**: Figma 가 공급원이고, 코드가 그 모양을 구현한다.
- **컴포넌트 API(속성·슬롯)**: `CLAUDE.md` 의 매핑 표가 공급원이고, Figma 와 코드가 둘 다 그 표를 따른다.

## 7-2. 상태는 세 곳에서 다른 이름으로 산다 (02강 예고)

같은 "상태"가 세 층에서 다른 이름으로 나타난다. 이 셋을 1:1로 맞추는 것이 연동의 핵심이다.

| 층 | 표현 | 예 |
|---|---|---|
| Figma | Component Set 의 **variant** | `checked=true` |
| Lit | `@property({ reflect: true })` → **HTML 속성** | `<ds-switch checked>` |
| React | **state** → props 로 전달 | `const [on, setOn] = useState(false)` |

상태의 소유자는 하나다. 누가 가지고, 거부는 어떻게 하고, 내부 상태(`@state`)는 왜 노출하지 않는지는 **02강(상태 연동)** 에서 `ds-switch` 와 `demo/react.html` 로 깊이 다룬다. 이 교재(01강)는 토큰과 컴포넌트까지다.

## 7-3. 새 컴포넌트 추가 체크리스트

새 `ds-<name>` 을 만들 때 아래를 지킨다(`README.md` 와 같은 내용).

- [ ] Figma variant 속성 → `@property({ reflect: true })` + `:host([attr="..."])` 스타일
- [ ] 색·간격·글꼴 값은 **반드시 `var(--ds-*)`** 로만 (직접 값 금지)
- [ ] 바깥에서 바꿔도 되는 곳만 `part=` 또는 `--ds-<컴포넌트>-*` 로 공개하고, JSDoc 에 `@csspart`·`@cssprop` 로 밝힘
- [ ] 폼 컨트롤이면 `static formAssociated = true` + `attachInternals()`
- [ ] `label` ↔ `input` 처럼 aria ID 참조가 필요한 요소는 같은 Shadow Root 안에 둠
- [ ] 이벤트는 `bubbles: true, composed: true` 로 Shadow 경계 밖까지 전달
- [ ] `src/index.ts` 에 export, `src/react/index.ts` 에 래퍼 추가

## 7-4. 알아 둘 한계

- **서버 렌더링(SSR)**: Next.js 처럼 서버에서 미리 그려야 하면 `@lit-labs/ssr` 를 검토한다(아직 labs 단계). 브라우저에서만 그리는 앱이면 문제 없다.
- **React 18 이하**: 커스텀 이벤트·객체 props 전달이 온전하지 않으므로 `@k3i/ds/react` 래퍼를 쓴다. React 19 이상은 태그를 직접 써도 된다(06장).

## 7-5. 자주 쓰는 명령 모음

| 명령 | 하는 일 |
|---|---|
| `npm install` | 라이브러리 설치 (처음 한 번) |
| `npm run dev` | 토큰 빌드 + 데모 실행 (`http://localhost:5173`) |
| `npm run tokens` | `tokens.json` → `src/styles/tokens.css` |
| `npm run figma:plugin` | `tokens.json` → `figma/plugin/code.js` (Figma 변수 임포터) |
| `npm run build` | `dist/` 에 라이브러리·타입·`tokens.css` 생성 |

## 마무리

여기까지 하면 한 가지 디자인을 Figma 와 코드 양쪽에서 같은 이름으로 다루고, 토큰·컴포넌트를 양방향으로 맞추고, 그 결과를 React·Vue·순수 HTML 에서 쓰는 전체 과정을 한 바퀴 돈 것이다.

- 더 깊이 보려면: `CLAUDE.md`(이름 규칙), `figma/LESSONS.md`(레슨별 프롬프트), `figma/SETUP.md`(연결·플랜).
- 다음 단계: **02강 — React × Lit 상태 연동** 에서 상태 소유와 거부 가능한 이벤트를 다룬다.
